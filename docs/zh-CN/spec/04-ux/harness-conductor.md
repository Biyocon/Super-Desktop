# 聊天中的 Harness Conductor

> **翻译说明：** 本页是与 [英文源规格](/spec/04-ux/harness-conductor) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 权限与入口

每个保留的桌面聊天在普通转录上方提供 **打开编排器** 按钮。这是独立的流程界面，
不是 Task 别名或外部 MCP 结果。关闭面板不取消宿主管理的运行。打开面板只读取历史，
绝不启动或恢复工作。持久会话决定代码仓库与 provider；原生、远程或未关联仓库的会话
不能在此启动运行。

The Emperor 表示授予有限委托的用户，不是额外的自主执行者。The Conductor 协调实际
Harness 交接。角色参考展示已有的 The Conductor、Detective、Strategist、
Devil’s Advocate、Headsman、Auditor、Integrator 和 The Arbiter 头像，并明确说明
这些不是正在运行的执行者。仅在存在已确认的 Ralph 派发时显示 Ralph，且标为 Headsman
的下级实现循环。

普通 Task 保留自身标识：内置 agent 使用准确名称与机器人图标，不推断专家权限。
仅展示实际 Task 节点；独立及重复任务分别保留。恢复链选择最新卡片，不改写旧转录。
用户 agent 的显式角色名头像只是装饰，不是流程权限。

## 委托表单

**新建运行** 提供只读分析或授权实现、目标、读取范围、排除路径、验收标准与可选输入
资料路径。实现还必须选择允许写入的路径与固定验证命令 ID。多项字段每行一项；路径
相对仓库并使用 `/`，不允许通配符、父目录跳转、别名或 `.git`。main、runtime 与 host
独立验证委托；renderer 不能选择可执行文件、镜像、项目路径或 provider 凭据。

首个固定命令为 `node-tests`，使用本地已有、摘要锁定的 Linux Node 镜像及
`/usr/local/bin/node --test --test-isolation=none`。不拉取镜像或安装 Docker。
验证进程只读挂载仓库，默认拒绝系统调用并禁止网络。这是有限的初始目录，不支持任意
项目命令。缺少本地前提时阻止实现，不降低隔离要求。

启动前保留请求 UUID，防止重复提交。**取消待处理的准入** 仅取消该请求，包括等待中的
输入资料 Read 权限。已有普通聊天工作或活跃 Conductor 准入会阻止竞争启动。即使 UI
元数据陈旧，host 仍是准入与生命周期的权威。

## 流程与证据

选定运行显示实际 host 生命周期、引擎状态、当前阶段及关卡、记录格式、源代码基线、
版本及下一步允许的转换。转换说明不能推进引擎。引擎来源信息包括源代码修订、运行时
版本、MIT 许可证、格式 5 与产物哈希。引擎缺失或不兼容时显示阻塞，不回退普通模型聊天。

执行者只来自已确认派发。每张卡片分别保留角色、执行者标识、派发标识、任务、模式、
输入哈希、状态与原始输出。执行者完成不代表关卡通过；即使复用执行者标识，独立派发
仍使用 dispatch ID 区分。

关卡面板显示引擎实际决定、依据、已审查证据、状态更新、下一阶段、缺陷分类及已有的
基线哈希。分析中的明确跳过显示为“不适用/跳过”及其理由，不显示通过。返工与下游
失效历史保留。报告的原始 JSON 与执行者输出分开。概览直接复制 motor record 中
The Arbiter 的 GO/NO-GO 或分析 accept/revise/blocked，不从文字推断。可检查原始
checkpoint/intake JSON 进行诊断。

固定格式 5 的驱动将有效 NO-GO 保存为精确的权威 Gate-G 升级记录
（`arbiter NO-GO — escalate to owner`），而不是 `run.decision`。缺少 decision 字段时，
只有该关卡记录可投影 NO-GO；执行者输出中的同样文字或其他升级记录不能触发该显示。

所有展开面板使用共享原生按钮、`aria-expanded` 及匹配的 `aria-controls`，供鼠标、
Enter 与 Space 操作。状态不仅依赖颜色。界面使用全部九个语言目录。来源与报告字符串
按纯文本显示，不执行其中的 HTML。

## 精确 Gate-C 决定与工具权限

实际等待所有者时，面板显示确切同意请求 ID、执行基线哈希、源代码指纹、范围/计划/
验收版本、允许/排除路径、回滚引用、验证定义哈希与影响配置。**批准此确切基线** 与
**拒绝此基线** 仅回答该请求，不乐观通过关卡或缓存授权。陈旧、已变化或其他运行的
请求被拒绝。文件工具权限仍独立；现有权限模式、敏感路径与审计规则继续约束实现写入。

GO 不授予 commit、push、merge、release、publish 或 deploy 权限。
`awaiting_authorization` 不被误标为 closed。此集成不执行外部操作，也不提供通用
所有者指令编辑器。需要尚不支持的所有者干预时，升级处理状态仍可见且阻塞，不转换为
同意请求或虚构的下一阶段。

## 历史与生命周期

Rust 管理持久运行、报告、关卡 checkpoint、派发回执与来源链。renderer 订阅只是失效
通知；controller 合并读取，拒绝陈旧 owner/run/选择/版本响应，挂载、重开或 reload
不重放 provider 请求、写入或派发。已释放监听器不能更新其他会话面板。effect 新一代
连接等旧读取结束后刷新当前状态。

取消等待自身资源清理。只有投影提供恢复选项时，中断历史才显示 **验证基线并恢复**。
恢复提交确切观察版本，重新验证来源/基线，必要时重新获得 Gate-C 同意。清理问题可见
并阻止恢复。来源影响回执失败不表示实际写入已经回滚。

## 验证状态

组件测试覆盖面板入口、精确同意展示、角色/执行者区分、匹配的关卡/报告面板、引擎缺失
阻塞与只读重开。controller 测试覆盖重复点击/通知、陈旧响应、选择切换、释放/重连与
精确同意标识。独立本地 API 链验收实际运行 preload/main/provider 解析、打包 sidecar、
未修改的 Harness、Rust 持久化、无害写入与独立 Docker 验证。上述均为 fixture 测试，
不是 live 模型质量验收。隔离整应用 fixture 验收已通过：实际表单入口与 Gate-C 批准、
41 次原生鼠标/Enter/Space 面板交互、十个截图哈希，以及 renderer reload 和自身应用
完整重启后历史一致、无 provider/派发/写入重放。最终已提交候选与 fork 集成资格另见
[验收矩阵](../../../project/harness-conductor-acceptance.md)。
